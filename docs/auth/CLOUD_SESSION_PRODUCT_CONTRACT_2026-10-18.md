# عقد جلسة السحابة — نموذج منتج احترافي

**الحالة:** العقد مُنفَّذ كحاجز فوق التطبيق (2026-10-18) — بلا تغيير مسارات الدخول  
**التاريخ:** 2026-10-18  
**المستوى:** سياسة منتج + هندسة — ليس تصميماً تنفيذياً

---

## 1) الحكم على الاقتراح

الاقتراح («إذا فُقدت الجلسة لا يبقى التطبيق يعمل كأنه طبيعي») **جيد وصحيح كسياسة وضوح**.

هو **غير كافٍ** إن نُفّذ كقاعدة واحدة:

> إذا `session == null` → شاشة تسجيل الدخول

شركة احترافية تفصل:

| طبقة | السؤال | الجواب في نابو |
|------|--------|----------------|
| الوقاية | كيف نقلل الموت الخاطئ؟ | إصلاح المهلة/`signOut` (منفّذ موضعياً) |
| الكشف | كيف نعرف أن السحابة ميتة؟ | حالات صريحة أدناه |
| الاحتواء | ماذا يبقى يعمل؟ | تشغيل محلي محدود |
| الإلزام | متى نمنع الاستمرار؟ | فقط عند فقدان **نهائي** للجلسة |
| الاستعادة | إلى أين نذهب؟ | شاشة إعادة ربط — لا logout كامل افتراضياً |

---

## 2) عقد المنتج المعتمد للدراسة

**الاسم:** `cloud-soft-gate`  
**ليس:** `cloud-required` (بدون سحابة لا يُفتح المحل)  
**ليس:** `silent-local` (يعمل بلا أي إشارة — الوضع الحالي المعيب)

### الوعد للمستخدم

1. المحل يستطيع البيع محلياً عند ضعف الشبكة.  
2. لا تُخفى حالة السحابة أبداً.  
3. واتساب البطاقات والمزامنة والأجهزة **لا تُقدَّم كأنها تعمل** إذا الجلسة غير صالحة.  
4. عند الموت النهائي للجلسة: شاشة **إعادة ربط الحساب**، مع الإبقاء على بيانات الجهاز المحلية.  
5. لا يُطلب «مسح بيانات التطبيق» كمسار رسمي.

---

## 3) آلة الحالات (النموذج)

```
CONNECTED
  الجلسة موجودة والرمز صالح أو جُدّد بنجاح
  → كل الميزات السحابية مسموحة
  → لا بانر

DEGRADED
  فشل تجديد مؤقت (مهلة / شبكة) والجلسة ما زالت موجودة
  → بانر: «السحابة غير مستقرة — نعيد المحاولة»
  → البيع المحلي مسموح
  → واتساب/رفع لقطة: إعادة محاولة أو تعطيل مؤقت برسالة واضحة
  → لا إخراج من التطبيق

CLOUD_LOCKED
  الجلسة null، أو رفض تجديد نهائي (refresh token مرفوض)
  → شاشة «إعادة ربط الحساب» (حاجز أمام الميزات السحابية)
  → لا تُعرض قائمة أجهزة فارغة بصمت
  → لا يُرسل واتساب البطاقات
  → البيانات المحلية لا تُمسح
  → استعادة: Google / كلمة داخلية مخزّنة / PIN المالك حسب المسار الحالي
  → زر اختياري صريح: «متابعة محلية بدون سحابة» إن فشل الربط
       (يبقى CLOUD_LOCKED للسحابة، ويفتح التشغيل المحلي فقط)

RECONNECTING
  المستخدم ضغط إعادة الربط والطلب جارٍ
  → لا حلقة طرد إلى login
```

### قاعدة ذهبية

| الحدث | الحالة الناتجة | إخراج لشاشة الدخول الكاملة؟ |
|-------|----------------|------------------------------|
| timeout / شبكة | `DEGRADED` | لا |
| JWT منتهٍ + شبكة | `DEGRADED` مع تحذير أقوى | لا في المحاولة الأولى |
| `currentSession == null` بعد رفض نهائي | `CLOUD_LOCKED` | لا — شاشة إعادة ربط |
| المستخدم اختار خروجاً كاملاً بنفسه | login | نعم — قراره |

**طرد فوري إلى login لكل غياب جلسة = مرفوض في هذا العقد** لأنه يعاقب الشبكة ويخالف offline-first.

---

## 4) ماذا يُقفل في `CLOUD_LOCKED`

| مسموح | ممنوع حتى يعود `CONNECTED` |
|-------|------------------------------|
| فواتير/بطاقات محلية في SQLite | إرسال واتساب بطاقة من التطبيق |
| تقارير محلية | رفع لقطة / مزامنة كتابة |
| بوابة PIN للموظفين على نفس الجهاز | اعتبار الجهاز «متصلاً» في الحساب |
| قراءة آخر بيانات محلية | إخفاء العَرَض |

## 5) شاشة إعادة الربط (مواصفات منتج)

عنوان: **انقطع ربط الحساب بالسحابة**  
نص: التطبيق على هذا الجهاز ما زال يحتفظ ببيانات المحل. لإرسال واتساب ومزامنة الأجهزة يلزم إعادة الربط.

أزرار بالترتيب:

1. **إعادة الربط** (استعادة صامتة ثم Google إن لزم — تفاعل واحد واضح)  
2. **متابعة بدون سحابة** (ثانوي، ليس الافتراضي المخفي)  
3. لا زر «امسح بيانات التطبيق»

فشل الربط → البقاء على نفس الشاشة مع سبب قصير (شبكة / يحتاج Google). **ممنوع** حلقة: فشل → login → فشل → login.

---

## 6) ما لا يُعتبر حلاً مهنياً

- إبقاء التطبيق صامتاً مع جلسة ميتة (الوضع الذي اشتكى منه المستخدم).  
- `if (session == null) Navigator → /login` بدون تمييز Transient.  
- مسح SQLite أو `deviceOwnerBound` عند `CLOUD_LOCKED`.  
- اعتبار الإصلاح الجراحي للمهلة كافياً وحده لإغلاق شكوى «يشتغل وكأنه متصل».

---

## 7) معايير قبول (عند التنفيذ لاحقاً)

1. مهلة شبكة لا تُخرج المستخدم ولا تستدعي `signOut`.  
2. رفض refresh نهائي يفتح شاشة إعادة الربط خلال استئناف التطبيق، لا بعد أيام من العمل الصامت.  
3. واتساب البطاقات لا يُحاول كنجاح وهمي في `CLOUD_LOCKED`.  
4. قائمة الحساب لا تعرض «لا أجهزة» بلا جملة «السحابة غير مربوطة».  
5. بيانات المحل المحلية تبقى بعد القفل وبعد إعادة الربط.  
6. اختبارات حالات: CONNECTED / DEGRADED / CLOUD_LOCKED — تفشل إذا اختلطت.

---

## 8) علاقة بالعمل المنفّذ

| موجود | ناقص لهذا العقد |
|-------|-----------------|
| منع `signOut` على مهلة التجديد | آلة الحالات في الواجهة |
| استعادة صامتة | شاشة إعادة ربط |
| نبضة بمهلة | بانر دائم في `DEGRADED` |
| — | قياس سبب الانتقال بين الحالات |

**هذا الملف عقد منتج. ليس أمراً بالتنفيذ.**
