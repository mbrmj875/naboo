# سيناريو يدوي: نفس الحساب هاتف + ويب

## قبل البدء
1. طبّق `admin-web/supabase/app_register_device_web_policy.sql` في Supabase SQL Editor (مرة واحدة).
2. ابنِ وانشر الويب: `./scripts/build_web.sh` ثم انشر `/app/`.
3. بوابة انحدار: `./scripts/ci_web_native_smoke.sh` (ويب + APK debug).

## سيناريو A — نفس الحساب
1. على Android: سجّل دخول بحساب المالك، أنشئ منتجاً أو عدّل كمية (أوفلاين ثم اتصل وزامن).
2. على المتصفح: نفس الحساب → بعد السحب يجب أن تظهر البيانات.
3. على الويب: عدّل إعداداً أو سجّل ملاحظة ديون/تقرير (قراءة/كتابة وصفية) وتحقق من الظهور بعد المزامنة على الهاتف.

## سيناريو B — بيع ويب بعد event-merge
1. هاتف أوفلاين: بيع منتج ينقص المخزون (لا تزامن بعد).
2. ويب: forcePull (تلقائي قبل البيع) ثم بيع نفس المنتج.
3. هاتف: اتصل وزامن — الكمية يجب أن تعكس البيعَين (خط أساس السحابة + بنود فاتورة محلية غير الواردة).

## سيناريو C — خمول وlogout
1. ويب: انتظر 15 دقيقة بلا تفاعل → قفل واجهة فقط (DB يبقى).
2. خروج نهائي مع طابور مزامنة غير فارغ → تحذير «ارفع الآن أو احذف محلياً».

## طباعة حرارية (POC)
على جهاز الكاشير: `python3 infra/print_bridge/bridge.py` ثم اطبع من الويب إلى `127.0.0.1:19100`.
