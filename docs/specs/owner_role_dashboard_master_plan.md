# الخطة النهائية المعتمدة — دور صاحب العمل ولوحة المتابعة

## حالة الوثيقة
- الحالة: معتمدة كمرجع دائم
- النطاق: المراحل 1 و2 و3 (منجزة)
- آخر تحديث: 2026-05-27

## القرار المعماري الملزم
**Single Organization + Multi-Device**

- النظام يعمل بمؤسسة واحدة (Single Org).
- تعدد الأجهزة والمستخدمين التشغيليين يتم داخل نفس المؤسسة.
- لا يوجد توسيع إلى `multi-org` في النطاق الحالي.
- المرحلة 4 (إن فُتحت) تكون أمن/تدقيق/مزامنة فقط، وليست إعادة تصميم تنظيمي سحابي.

## المبادئ الأربعة الملزمة
1. **لا نظام صلاحيات موازٍ**: التوسعة تتم داخل `PermissionService`/`PermissionKeys` القائمين.
2. **تنفيذ Atomic للمرحلة 1**: bypass الوردية للمالك لا يُعتمد إلا بعد تغطية كل نقاط التوجيه ذات الصلة.
3. **عدم خلط الطبقات**: فصل واضح بين سياق tenant السحابي وسياق الفروع المحلية في SQLite.
4. **لا توسّع RLS بلا متطلب منتجي مستقل**: أي تغيير سحابي كبير يتطلب قرار منتج جديد.

## سياسة الأدوار المعتمدة
- الأدوار: `owner`, `admin`, `staff`.
- `owner`: إشراف كامل + bypass الوردية + إدارة عليا.
- `admin`: إدارة تشغيلية ضمن السياسة المعتمدة (بدون صلاحيات owner).
- `staff`: تشغيل نقطة البيع ضمن صلاحيات مفصلة.

### قرارات الحوكمة المعتمدة
- عدد الـ owners في المرحلة 2: **Owner واحد فقط**.
- `admin` يمكنه إنشاء `staff` فقط.
- منع `admin -> admin` و`admin -> owner`.
- حماية owner الوحيد من:
  - التعطيل
  - تخفيض الدور
  - التعطيل الذاتي (self-deactivation)

## نطاق المراحل المنجزة

## المرحلة 1 — Owner Shift Bypass (Atomic)
- الهدف: استثناء صاحب العمل من Shift Gate دون كسر سلوك باقي الأدوار.
- النتيجة: توجيه owner إلى `/home`، وإبقاء staff/admin ضمن سلوك الوردية الحالي.
- تغطية acceptance: 5/5 PASS.

## المرحلة 2 — Owner Governance
- الهدف: حماية إدارية تمنع قفل النظام وتقيّد عمليات الإدارة الحساسة.
- النتيجة:
  - حماية owner الوحيد على مستوى DB/UI.
  - تقييد admin إلى staff-only في الإنشاء/الترقية.
  - تمييز owner بصرياً في الواجهة.
- تغطية acceptance: 6/6 PASS.

## المرحلة 3 — Owner Dashboard MVP
- الهدف: واجهة متابعة مخصصة للمالك بدل واجهة POS التشغيلية.
- النتيجة:
  - Resolver لمسار `/home` (owner -> `OwnerDashboardScreen`).
  - Tenant Switcher مرتبط بـ `TenantContextService`.
  - KPI مبيعات اليوم حسب الفرع المختار.
  - قائمة الورديات المفتوحة.
  - اختصارات التقارير والمستخدمين.
  - دعم Offline عبر SQLite المحلي.
- تغطية acceptance: 10/10 PASS.
