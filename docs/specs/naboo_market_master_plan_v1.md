# 1. الملخص التنفيذي

**Naboo Market** هو التطبيق الذي يحمّله **المستهلك العادي** (ليس التاجر) لـ:

- تصفّح منتجات محلات حيه
- البحث والمقارنة
- الطلب والدفع (COD أولاً)
- الاستلام من **نقطة PVZ** قريبة (نموذج Ozon)
- تتبّع الطلب والتقييم

```
┌─────────────────────────────────────────────────────────────┐
│  الهدف: تجربة «سوق شامل محلي» مثل Ozon/Wildberries          │
│  لكن مكيّفة للعراق: COD · حي واحد · PVZ · عربي RTL          │
│  الربح: لا من المستهلك — من عمولة البيع على التاجر         │
└─────────────────────────────────────────────────────────────┘
```

**مبدأ Pilot:** التطبيق يبدأ **بسيطاً جداً** (10–20 محل، حي العشار) ثم ينمو feature-by-feature نحو تجربة Ozon كاملة — لا نبني كل شيء دفعة واحدة.

# 2. مقارنة Ozon / Wildberries — ماذا نأخذ وماذا نؤجّل

## 2.1 جدول المقارنة

| ميزة Ozon / WB | Naboo Market | المرحلة |
|----------------|--------------|---------|
| سوق متعدد البائعين | ✅ | Pilot |
| بحث عبر كل المتاجر | ✅ | V1 |
| صفحة منتج غنية (صور، متغيرات) | ✅ | Pilot (مبسّط) |
| سلة من متاجر متعددة | ✅ | V1 |
| **PVZ** — استلام من نقطة قريبة | ✅ **جوهر النموذج** | Pilot |
| توصيل منزلي | ⏳ | V2+ |
| دفع إلكتروني (بطاقة، محفظة) | ⏳ | V2 (بعد COD) |
| توصيات ذكية في الرئيسية | ⏳ قواعد → AI | V1 → V2 |
| إعلانات مدفوعة للتجار | ⏳ | V3 |
| برنامج ولاء / نقاط | ⏳ | V2 |
| مقارنة منتجات | ⏳ | V3 |
| فيديو منتج / بث مباشر | ❌ | بعيد |
| شحن دولي | ❌ | خارج النطاق |
| اشتراك Prime | ❌ | **مرفوض** — Market مجاني |

## 2.2 الفرق الجوهري عن Ozon

| Ozon | Naboo |
|------|-------|
| بنى 50,000 PVZ باستثمار ضخم | كل محل Naboo = PVZ محتمل |
| تجار محترفون أونلاين | **Pilot:** تجار offline — catalog من Concierge |
| لوجستيك مركزي | مندوب منصة → لاحقاً شبكة P2P |
| روسيا — بطاقات منتشرة | العراق — **COD 95%+** في البداية |

## 2.3 موقع Wildberries

Wildberries تركّز على **الموضة + سرعة التوصيل + إرجاع سهل**. Naboo في Pilot:

- **لا** نركّز على الموضة فقط — سوبرماركت + ملابس + إلكترونيات
- **إرجاع:** نافذة 5 أيام (مذكورة في ecosystem plan)
- **السرعة:** لا ننافس 30 دقيقة — ننافس **ثقة الحي + سعر المحل**

# 3. المنصات: iOS · Android · Web

## 3.1 القرار التقني

| المنصة | التقنية | الأولوية |
|--------|---------|----------|
| **Android** | Flutter (مشروع `naboo_market`) | 🔴 Pilot |
| **iOS** | نفس الكود Flutter | 🔴 Pilot |
| **Web** | Flutter Web **أو** Next.js للصفحات العامة | 🟡 V1 |

**التوصية:**

```
Pilot:     Flutter → Android + iOS فقط
V1:        + Flutter Web (نفس الكود) للتصفّح والطلب
V1.5:      صفحات SEO عامة (Next.js أو SSR) لمنتجات/متاجر — فهرسة Google
```

## 3.2 لماذا Flutter لمشروع مستقل؟

- ERP موجود بـ Flutter — نفس المهارات والأنماط (Provider، RTL، Tajawal)
- **كود واحد** لثلاث منصات
- package مشترك `naboo_shared`: تنسيق IQD، enums، ألوان العلامة

## 3.3 Web — تجربة Ozon-like على المتصفح

| العنصر | المواصفة |
|--------|----------|
| عرض | responsive: موبايل 360px → ديسكتوب 1440px |
| PWA | «أضف إلى الشاشة الرئيسية» — يشبه تطبيقاً |
| SEO | `/p/{slug}` و `/store/{slug}` قابلة للفهرسة (V1.5) |
| Deep links | `naboo.market/p/...` و `naboo://order/...` |
| بدون تسجيل | تصفّح كامل — تسجيل عند الطلب فقط |

## 3.4 متطلبات المتاجر

| المتجر | الحد الأدنى |
|--------|-------------|
| Google Play | سياسة دفع — COD مسموح؛ لا IAP لمنتجات مادية |
| App Store | نفس المبدأ — لا تجاوز Apple IAP لاشتراكات رقمية وهمية |
| Web | HTTPS، سياسة خصوصية عربية |

# 4. هيكل التطبيق والتنقّل

## 4.1 التنقّل الرئيسي (Bottom Nav — موبايل)

```
┌──────────┬──────────┬──────────┬──────────┬──────────┐
│  الرئيسية │  التصنيفات│  السلة   │  طلباتي  │  حسابي   │
│  🏠       │  📂      │  🛒      │  📦      │  👤      │
└──────────┴──────────┴──────────┴──────────┴──────────┘
```

**تابلت/ديسكتوب:** `NavigationRail` يمين (RTL) + محتوى أوسع.

## 4.2 تدفق المستخدم الأساسي

```
فتح التطبيق
    → اختيار الحي / نقطة الاستلام (أول مرة)
    → الرئيسية (مخصّصة)
    → بحث أو تصنيف
    → صفحة منتج
    → إضافة للسلة
    → Checkout (PVZ + COD)
    → طلباتي (تتبّع)
    → استلام من PVZ + دفع
    → تقييم
```

## 4.3 الزائر vs مسجّل

| الحالة | الصلاحيات |
|--------|-----------|
| **زائر** | تصفّح، بحث، سلة — **تسجيل عند Confirm Order** |
| **مسجّل** | OTP جوال، طلبات، عناوين، تفضيلات، إشعارات |

# 5. الشاشات والتجربة — تفصيل UX

## 5.1 الشاشة الرئيسية (Home)

**الهدف:** يشعر المستخدم أن التطبيق «يعرفه» — مثل Ozon/WB.

### أقسام الرئيسية (من الأعلى للأسفل)

| # | القسم | المحتوى | Pilot | V1+ |
|---|--------|---------|-------|-----|
| 1 | **شريط علوي** | شعار · شريط بحث · أيقونة PVZ المختارة | ✅ | ✅ |
| 2 | **الموقع** | «العشار — استلام من: [متجر X]» — قابل للتغيير | ✅ | ✅ |
| 3 | **بانرات** | عروض، 0% توصيل، أول طلب | ✅ يدوي | ✅ مستهدف |
| 4 | **اختصارات تصنيفات** | أيقونات دائرية: بقالة، ملابس، إلكترونيات… | ✅ 6–8 | ✅ 12+ |
| 5 | **لك خصيصاً** | منتجات مخصّصة (AI/قواعد) | ⏳ قواعد | ✅ AI |
| 6 | **الأكثر مبيعاً في حيك** | trending حسب الحي | ✅ | ✅ |
| 7 | **متاجر قريبة** | بطاقات محلات مع تقييم | ✅ | ✅ |
| 8 | **عروض اليوم** | خصومات محدودة | ⏳ | ✅ |
| 9 | **شاهدت مؤخراً** | آخر 10 منتجات | ✅ | ✅ |
| 10 | **قد يعجبك** | مشابه لما اشترى/شاهد | ⏳ | ✅ |
| 11 | **إعادة الطلب** | بنود من طلبات سابقة | ⏳ | ✅ |

**قاعدة UX:** كل قسم = `ListView` أفقي أو شبكة 2 عمود — **pagination** — لا تحميل كامل.

## 5.4 صفحة المتجر (Storefront)

| عنصر | يظهر للمستهلك؟ |
|------|----------------|
| اسم المتجر | ✅ |
| شعار · غلاف | ✅ |
| التقييم | ✅ |
| الحي فقط (مثلاً «العشار») | ✅ اختياري — **ليس** عنواناً |
| **عنوان الشارع / المنزل** | ❌ **ممنوع** |

## 5.5 صفحة المنتج (PDP)

**مثل Ozon — بسيطة في Pilot:**

| منطقة | المحتوى |
|-------|---------|
| معرض صور | swipe، pinch zoom |
| السعر | `12,500 د.ع` — `compare_at` مشطوب إن وُجد |
| الشارة | «متوفر» / «كمية محدودة» / «نفد» |
| المتجر | «يباع بواسطة: **اسم المتجر**» — **بدون عنوان** |
| المتغيرات | لون، مقاس (إن وُجد `variants_json`) |
| CTA ثابت أسفل | «أضف للسلة» — لون بارز |
| أسفل الصفحة | وصف · مواصفات · منتجات مشابهة |

**حالات إلزامية:** loading · empty (منتج محذوف) · error · غير متوفر.

## 5.6 السلة

- تجميع حسب **البائع** (كل بائع = شحنة منفصلة محتملة)
- تعديل كمية · حذف
- ملخص: المجموع الفرعي · رسوم استلام (إن وُجدت) · **الإجمالي**
- **لا تظهر العمولة** للمستهلك أبداً
- CTA: «متابعة الطلب»

## 5.7 Checkout (3 خطوات)

```
الخطوة 1 — الاستلام
  ○ استلام من نقطة PVZ (افتراضي Pilot)
  ○ توصيل منزلي (معطّل في Pilot)

الخطوة 2 — الدفع
  ○ نقد عند الاستلام (COD) — افتراضي
  ○ Zain Cash / FIB / بطاقة (V2)

الخطوة 3 — المراجعة
  ملخص · ملاحظات · رقم جوال · تأكيد
  → رقم طلب NAB-20260620-0042
```

## 5.9 حسابي

- الملف الشخصي (اسم، جوال)
- عناوين / نقاط استلام مفضلة
- طرق الدفع المحفوظة (V2)
- الإشعارات (تفعيل/تعطيل حسب النوع)
- اللغة (عربي فقط في V1)
- الدعم — واتساب + FAQ

## 5.10 Onboarding (أول فتح)

```
شاشة 1: «مرحباً في نابو — تسوّق من محلات حيك»
شاشة 2: اختر حيك (العشار في Pilot)
شاشة 3: اختر نقطة استلام قريبة (خريطة أو قائمة)
شاشة 4: (اختياري) ما الذي يهمك؟ — بقالة · ملابس · إلكترونيات
         → يُغذّي التخصيص من اليوم الأول
```

3–4 شاشات فقط — **لا تطيل**.

## 5.11 خصوصية عنوان البائع — سياسة ثابتة

### القاعدة

```
Market للمستهلك:  اسم المتجر فقط — لا عنوان بائع
العنوان الكامل:   نقطة PVZ تجارية · أو داخلي (مندوب/ERP) فقط
```

**لماذا:** تجار من **المنزل** — عنوان السكن **لا يُعرض أبداً** للمشتري (مثل Ozon: علامة البائع بدون مستودعه).

### ماذا يرى المستهلك؟

| الشاشة | اسم البائع | عنوان |
|--------|------------|--------|
| منتج / متجر / بحث | ✅ | ❌ |
| اختيار **PVZ** | اسم **النقطة** | ✅ عنوان **النقطة** + خريطة |
| طرد جاهز | — | ✅ عنوان **PVZ** فقط |
| تتبّع الطلب | ✅ اسم البائع | ❌ عنوان بائع |

### من يرى عنوان البائع الحقيقي؟

| الدور | عنوان البائع (منزل/محل) |
|------|-------------------------|
| مستهلك Market | ❌ **أبداً** |
| مندوب نابو | ✅ شاشة ops داخلية |
| ERP التاجر | ✅ إعداداته |
| admin-web | ✅ تشغيل |

### أنواع الموقع

| النوع | Market يعرض |
|-------|-------------|
| `commercial` — محل | اسم + حي فقط |
| `home` — منزل | اسم + حي فقط (**إلزامي**) |
| `pickup_point` — PVZ | عنوان **عند الاستلام فقط** |

### API عام

- `marketplace_stores_public` — **لا** `internal_address` · **لا** `lat/lng` للبائع
- إحداثيات PVZ تُرجع فقط في `GET /pickup-points` و`order.pickup`

# 6. نظام التصميم (UI)

## 6.1 الهوية

| عنصر | القيمة |
|------|--------|
| الخط | **Tajawal** (مثل ERP) |
| الاتجاه | RTL دائماً — `ar_SA` |
| الأرقام | غربية 0–9 |
| العملة | `12,500 د.ع` — IQD فقط |
| الألوان | لون علامة Naboo + أخضر للنجاح + برتقالي للعروض |

## 6.2 مبادئ UX (مستوحاة من Ozon/WB)

1. **3 نقرات للشراء** — رئيسية → منتج → سلة → تأكيد (مع onboarding مرة واحدة)
2. **CTA واحد واضح** — زر «أضف للسلة» دائماً بنفس المكان
3. **صور كبيرة** — المنتج يُباع بالصورة في العراق
4. **ثقة بدون كشف عنوان البائع** — **اسم المتجر فقط** للمستهلك (انظر §5.11)
5. **لا فراغات** — skeleton loading بدل شاشة بيضاء
6. **أخطاء عربية واضحة** — «تعذّر تحميل المنتجات — إعادة المحاولة»

## 6.3 الكثافة حسب الشاشة

| الجهاز | أعمدة المنتجات | ملاحظات |
|--------|----------------|---------|
| موبايل < 640px | 2 | بطاقة منتج مضغوطة |
| تابلت 640–1024 | 3–4 | NavigationRail |
| ديسكتوب > 1024 | 4–6 | فلاتر جانبية ثابتة |

| **الرئيسية المخصّصة** | اكتشاف ضمني |
| **متجر معيّن** | ولاء لمحل |
| **إشعارات Push** | عودة للتطبيق |
| **مشاركة اجتماعية** | رابط منتج (V1.5) |
| **إعلانات مدفوعة** | تاجر يستهدف (V3) |

## 7.2 ترتيب النتائج (Ranking)

**Pilot — قواعد بسيطة:**

```
score = w1×قرب_PVZ + w2×مبيعات_الحي + w3×توفر + w4×تقييم - w5×سعر
```

**V2 — تعلم من البيانات:**

- نقرات · إضافات سلة · شراء · إرجاع (سالب)
- تخصيص per-user

## 7.3 «سوق موحّد»

المستهلك **لا يفرّق** بين متاجر في الواجهة — يرى منتجات. عند الطلب يظهر البائع. مثل Amazon/Ozon.

# 8. الذكاء الاصطناعي والتخصيص

> **التفاصيل الكاملة:** [`naboo_market_ai_personalization_v1.md`](./naboo_market_ai_personalization_v1.md) — إشارات التوقف · dwell · ملف الاهتمامات · Push · إعلانات

## 8.1 مراحل التخصيص

| المرحلة | الآلية | متى |
|---------|--------|-----|
| **P0 — قواعد** | اختيارات onboarding + تصنيفات + «الأكثر مبيعاً» | Pilot |
| **P1 — سلوكي** | شاهدت مؤخراً · مشابه لما في السلة · collaborative filtering بسيط | V1 (500+ مستخدم) |
| **P2 — بحث ذكي** | embeddings عربية · «ماء» يجد «مياه معدنية» | V2 |
| **P3 — LLM مساعد** | «أريد هدية لطفل 5 سنوات بـ 50 ألف» → منتجات | V3 |
| **P4 — إعلانات ذكية** | استهداف شرائح للتجار | V3 |

## 8.2 الرئيسية المخصّصة — كيف تعمل (P1)

```
مدخلات:
  - user_id (أو device_id للزائر)
  - أحداث: view, add_to_cart, purchase, category_click
  - الحي المختار
  - الوقت (صباح → بقالة · مساء → وجبات خفيفة)

مخرجات أقسام:
  - «لأنك شاهدت X» → منتجات مشابهة
  - «شائع في العشار» → trending محلي
  - «تسوق مجدداً» → إعادة طلب
  - «جديد في [متجرك المفضل]»
```

**تنفيذ تقني (لاحقاً — ليس Pilot):**

- تخزين أحداث في `marketplace_events` (Supabase)
- Edge Function ليلية: حساب `user_affinities` (تصنيف × وزن)
- قراءة سريعة عند فتح الرئيسية (< 200ms من cache)

## 8.3 الخصوصية

- لا بيع بيانات لطرف ثالث
- إعداد «تخصيص الإعلانات» — إيقاف في حسابي
- حذف بيانات السلوك عند طلب المستخدم
- لا تخزين محتوى حساس

## 8.4 ما لا نفعله في Pilot

- ❌ ChatGPT داخل التطبيق
- ❌ توصيات معقدة بدون بيانات
- ❌ تتبّع عبر تطبيقات أخرى

# 9. التسويق والنمو داخل التطبيق

## 9.1 استراتيجية النمو — مراحل

### المرحلة A — Pilot (العشار، 0–90 يوم)

| القناة | الإجراء |
|--------|---------|
| **Concierge** | أنت ترفع منتجات — لا انتظار SEO |
| **ملصقات QR في المحلات** | «اطلب أونلاين من متجرنا» |
| **واتساب حي** | مجموعات العشار — رابط تحميل |
| **أول طلب** | خصم 5,000 د.ع أو توصيل مجاني (يدوي) |
| **Push** | «طردك جاهز» — وليس spam |

### المرحلة B — V1 (توسع حي ثانٍ)

| القناة | الإجراء |
|--------|---------|
| **إحالة** | «ادعُ صديق» — رصيد 5,000 د.ع للطرفين |
| **إشعارات ذكية** | سلة متروكة · عرض ينتهي |
| **بريد/SMS** | OTP موجود — تذكير طلب جاهز |
| **محتوى** | «أفضل 10 منتجات في العشار هذا الأسبوع» |

### المرحلة C — V2+

- SEO لصفحات المنتجات
- حملات فيسبوك/إنستغرام مستهدفة بالحي
- برنامج ولاء نقاط
- عروض flash (عدّاد تنازلي)

## 9.2 أنواع العروض داخل التطبيق

| النوع | مثال | من يمول |
|-------|------|---------|
| **بانر رئيسية** | «شحن مجاني أول طلب» | Naboo (تكلفة اكتساب) |
| **شارة منتج** | «-20%» | التاجر |
| **قسيمة** | `ASHAR5` — 5,000 د.ع | Naboo أو تاجر |
| **توصيل مجاني** | فوق 50,000 د.ع | مشترك |
| **تاجر مميز** | ظهور أعلى في التصنيف | **إعلان مدفوع (V3)** |

## 9.3 Push Notifications — جدول الرسائل

| الحدث | التوقيت | نص مثال |
|-------|---------|---------|
| قبول الطلب | فوري | «تم قبول طلبك #123 من متجر الأمل» |
| جاهز للاستلام | فوري | «طردك في بقالة السلام — رمز: 482917» |
| تذكير استلام | +48 ساعة | «لم تستلم طردك — ينتهي خلال 3 أيام» |
| سلة متروكة | +2 ساعة | «نسيت شيئاً؟ أكمل طلبك» |
| عرض شخصي | أسبوعي max 1 | «منتجات بقالة بخصم — لأنك تتسوّق غالباً» |
| إعادة طلب | +14 يوم من الشراء | «هل تريد إعادة طلب [منتج]؟» |

**قاعدة:** لا أكثر من **3 push تسويقية/أسبوع** — الباقي معاملاتي فقط.

## 9.4 Onboarding التسويقي

- السؤال «ما الذي يهمك؟» في أول فتح → يخصّص الرئيسية فوراً
- شعور **فوري بالقيمة** — منتجات حقيقية من محلات يعرفها في حيه

## 9.5 مقاييس التسويق (Funnel)

```
زائر → تثبيت → فتح → تصفّح → إضافة سلة → checkout → طلب → تسليم → تقييم → إعادة شراء
```

تتبّع كل خطوة في Analytics (قسم 13).
